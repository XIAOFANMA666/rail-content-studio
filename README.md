# 轨道 · AI 生产运营中台

面向出海火车票短视频团队，以任务串联选题、脚本、制作、审核、发布登记和复盘。保留已有脚本编辑、AI 粗剪、成片评测和数据复盘能力。

本分支 `codex/operations-hub` 按《需求分析 2.0》2026-11-11 读取的 revision 592 调整页面。入口为生产总览；原 `#scripts`、`#create`、`#evaluate` 等链接继续可用。

## 本版页面与边界

- **生产总览**：已有脚本自动列为任务，可新建任务、填写负责人及交付日期、按阶段和关键词筛选。
- **选题策划**：记录创作要求和参考资料；生成脚本时传递创作要求。参考链接仅作交接记录，不会自动读取或拆解视频。
- **脚本工作室与制作工作台**：沿用脚本库、历史版本、AI 改写、配音与粗剪。页面要求先确认对应脚本版本，再进入制作；修改后须重新确认。
- **审核中心与发布管理**：上传成片时可人工关联当前任务，记录评测结果、终审人及意见。当前版本未记录终审通过时，页面锁定发布登记；发布由运营到平台人工完成，再登记账号、时间和作品链接。
- **内容资产与数据复盘**：搜索既有素材，查看剪辑规则与来源。复盘保留原 CSV 模拟数据，未把本机任务登记伪装成平台真实取数。

任务交接、负责人、确认与发布登记属于**浏览器本地流程原型**，保存在当前站点的 `localStorage`；换浏览器、换端口或清除站点数据不会共享这些记录。脚本库仍保存在本机 `output/`。页面门槛不等于服务端角色权限；团队账号、任务独立制作空间、多人协作与完整审计尚未实现。现有流水线仍共用最近一次运行目录，不支持多任务并行制作。

本次未修改需求云文档，也未将文档第五章中的计划功能改成已完成。

[在线演示](https://xiaofanma666.github.io/rail-content-studio/) · [来源仓库](https://github.com/ethan17461/ai-roughcut-demo)

## 拉取并查看（无需密钥）

需要 Git 和 Python 3.9 或更新版本。仓库包含 53 段示例视频，完整下载约 160 MB。

```bash
git clone https://github.com/XIAOFANMA666/rail-content-studio.git
cd rail-content-studio
python3 studio.py
```

打开 <http://localhost:8770>。首次启动自动加载随仓库附带的运行结果，可以播放、搜索素材、预览原片、替换预览镜头和查看复盘，无需安装模型依赖或填写密钥。Windows 如没有 `python3` 命令，使用 `python`。

8770 被占用时，macOS / Linux 使用 `PORT=18770 python3 studio.py`，然后打开 <http://localhost:18770>。按 Ctrl+C 停止服务。

## 生成自己的粗剪（macOS）

完整流水线使用 macOS 的 `afconvert`；没有 MiniMax 配音服务时会使用 `say`。Windows / Linux 可查看演示，完整生成流程尚未在这两个系统验证。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

在本机 `.env` 中填写模型服务密钥，再运行：

```bash
python studio.py
```

- 写脚本：配置 `DEEPSEEK_API_KEY`，或 `SCRIPT_BASE_URL`、`SCRIPT_API_KEY`、`SCRIPT_MODEL`。
- 配音：配置 `MINIMAX_API_KEY`；未配置时回退到 macOS 系统语音。
- 成片评测：配置支持图像输入的模型，填写 `VIDEO_BASE_URL`、`VIDEO_API_KEY`、`VIDEO_MODEL`。兼容格式见 `.env.example`。
- 在“选题与脚本”页输入选题，点“生成脚本”；三版中英文脚本直接显示在页面上，生成脚本不会改变现有预览或配音。
- 脚本自动收入本地脚本库，可按选题搜索、打开历史版本。旧版留存的最近三版会自动识别；也可点“收录当前作品”保存当前预览作品的脚本。
- 点“编辑 / 改写”修改英文口播、中文、花字、画面标签和地点；保存时另建历史版本，原稿保留。手动编辑和保存无需模型密钥。
- 在编辑窗口填写修改意见，点“AI 改写预览”，核对前后对照并保存。AI 会参考窗口中当前的修改稿；预览不会覆盖原稿，失败时保留窗口内容。
- 点击某版的“选用此版”，再点“生成配音与粗剪”。制作锁定选中的已保存版本，不再次调用脚本模型。修改脚本不会自动更新旧配音和粗剪，需要重新制作。
- 脚本库保存在 `output/script-library.json`，刷新或重启服务后保留，不自动同步云端或 Git。备份时请保留整个 `output/`；原 `script-session.json` 会保留作为迁移来源。
- 替换镜头后点“写入剪映”，再在剪映中精修。
- 模型调用会产生费用。成片评测会发送抽取画面和转写文本；本地语音识别首次使用还需下载模型。

`.env`、本机生成结果与虚拟环境均不提交。每位使用者配置自己的密钥。

## 各环节如何连接

页面左下角的“流程与连接”提供操作路径、交接内容和本机配置状态。密钥已配置不代表余额充足或调用已成功。

```mermaid
flowchart LR
    A[输入选题] --> B[模型生成三版脚本]
    B --> C[人工选用一版]
    C --> D[配音、字幕、素材匹配]
    D --> E[本机剪映工程]
    E --> F[剪映人工精修]
    F --> G[剪映导出 MP4]
    G --> H[手动上传工作台评测]
    H -->|需修改| F
    H -->|人工终审通过| I[运营去平台发布]
    I -.真实平台数据接口未接通.-> J[数据复盘：目前为演示记录与 CSV]
```

- **模型连接**：浏览器请求本地 `studio.py`，由服务端读取 `.env` 调用脚本或评测 API；密钥不进入页面。
- **配音与素材**：MiniMax 可选，无配置时用 macOS 系统语音；素材按本地标签匹配，未接云端素材库或全网检索。
- **剪映交接**：通过整个工程文件夹交接，不直接控制剪映。剪映内修改不会自动写回工作台。
- **成片评测**：手动上传 MP4；本地转写、抽帧后，将画面和转写文本送到评测模型。
- **发布与数据复盘**：没有平台自动发布、账号授权或自动取数。当前 `review.py` 读取 `data/review/report_*.csv` 并结合已有发布记录生成 `data/review/review.json`，页面展示该结果；无前端 CSV 导入入口。复盘结果不会自动改写新脚本。

## 在剪映专业版中打开

1. 在本地工作台生成配音与粗剪。程序会创建包含素材、配音、字幕和花字的工程文件夹；若换过镜头，先点击“写入剪映工程”保存修改。
2. 点击“素材与粗剪”页顶部的“导入剪映指引”，查看本次工程名称与真实路径。默认位于 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft/`。
3. 打开剪映专业版，在草稿列表中查找同名工程。剪映已打开时，完整退出后重开；仍未出现时，核对剪映设置中的草稿目录，将**整个工程文件夹**复制到实际目录，保留 `materials/`，不要只复制 JSON。
4. 在剪映检查画面、声音和字幕，精修后使用剪映的“导出”输出 MP4，再上传到工作台做成片评测。

工作台同时支持可编辑剪映工程与粗剪 MP4 导出。剪映客户端内的打开与导出尚未实测，不同版本的兼容性仍需验证。

### 直接导出粗剪 MP4

在「制作工作台」点击「导出粗剪 MP4」，完成后自动下载，也可点击「下载 MP4」再次获取。导出使用点击时当前预览的镜头（包括尚未写入剪映的替换）、已有配音、英文字幕和花字，输出 1080 × 1920、30 fps、H.264/AAC 文件。原素材声音静音，不额外生成配音或调用模型。

文件保存在 `output/exports/`，每次导出保留独立文件。字幕与花字烧录进视频，使用基础样式；不包含在剪映客户端内另做的精修、特效或音乐，也不会覆盖剪映工程。需要本地 FFmpeg 支持 `subtitles` 滤镜；优先复用系统 FFmpeg，再尝试已有的 imageio-ffmpeg。仅本地工作台支持，静态在线回放页不能导出。

## 视频热点与真实平台数据

- 「选题策划 → 视频热点」支持按平台、关键词、地区和近 1／7／30 天手动采集。YouTube 已实现官方搜索＋视频统计；TikTok／Instagram 已实现标准 JSON 数据服务接收器，需选定供应商并适配字段。配置与格式见 [接入说明](docs/video-hotspots.html)。本次尚无凭据，未实测真实平台取数；不能将代码测试通过视为三平台已接通。
- `video_trends.py` 管理采集、验证、原链接标准化、去重更新、分平台错误和原子保存。`GET /api/video-trends` 只读本地缓存（同时清理过期数据），`POST /api/video-trends/collect` 从工作台同源手动触发；请求示例 `{"query":"train travel","region":"GB","days":7,"platforms":["YouTube"]}`。每次间隔至少 30 秒，读取不消耗平台额度。
- 数据保存到忽略提交的 `output/video-trends.json`，最多 500 条，读取或采集时清理 30 天未重新取得的数据。指标缺失保留 null，不伪造零值；新批次失败保留旧数据，旧指标时间不会覆盖新指标。页面区分发布时间和取数时间；不下载视频、不自动发布、不创建定时任务。
- 视频列表仍合并 AIHOT 已公开收录的原视频链接，文章不会当作视频。选定平台后分别查看指标，不做跨平台热度分。当前未开发 Shorts 专属识别或供应商专有 OAuth。
- 本地 AIHOT 默认 API 为 `http://127.0.0.1:3301`、网页为 `http://127.0.0.1:3300`，可用 `.env` 中的 `AIHOT_API_URL`、`AIHOT_SITE_URL` 修改。AIHOT 需另行部署，不包含在本仓库中。历史参考只检查最新 6 条公开历史记录，不等于检索完整历史库。
- 「数据复盘 → 真实数据接入说明」：[CSV 与平台 API 接入路径](docs/platform-data.html)。平台授权、真实账号取数和更多指标字段尚未接通；配置说明不等于完成接入。


## 素材库（feat/media-library）

本地「内容资产」新增找素材、待审批、正式素材库及搜索/分析任务：
输入需求或从粗剪分句补素材 → Pexels 官方搜索 → 下载与规格检测 → 八帧采样 AI 初审 → 人工审批 → 入库查询与粗剪调用。

- 在 .env 填写 PEXELS_API_KEY；搜索需求拆解沿用 SCRIPT_*，画面分析沿用支持图像输入的 VIDEO_*。
- 安装系统 FFmpeg，确保 ffmpeg 和 ffprobe 均在 PATH。未配置画面模型时明确显示分析未执行，可人工审核并记录依据。
- 审批要求检查完整原片、核对来源授权与用途，地点不确定时留空。AI 风险和来源证据保留。
- 新素材保存在忽略提交的 output/media/，数据库在 output/media-library.sqlite3。备份整个 output/。
- 审批通过素材进入粗剪读取；候选、驳回、待补充、停用素材不参与新增召回。
- 保留历史 53 条素材，不为历史数据补造审批记录。静态展示页不执行联网或审批。
- 本地单人流程，无团队身份或多人权限；关键帧抽样初审不等于全片审核。
- 实施范围、启动、边界和集中验收清单见 [素材库说明](docs/media-library.md)。
- 环境恢复后，Python 语法、124 项回归、DOM 交互及本地视频/工程处理已通过。真实 Pexels 与画面模型联调、浏览器视觉及剪映客户端验收仍待完成；详细范围见素材库说明。
