准备位置

平台本机 .env 配置项下一步
YouTubeYOUTUBE_API_KEY启用 YouTube Data API v3，创建受限 API Key。之后开发并验证关键词搜索、视频统计和入库。
TikTokVIDEO_TRENDS_TIKTOK_FEED_URL确定可授权使用的视频发现／热点数据服务。账号自身的视频查询权限不能代替全平台热点搜索。
InstagramVIDEO_TRENDS_INSTAGRAM_FEED_URL确定可授权使用的 Reels 发现／热点数据服务；自身账号 Insights 与发现其他账号的热点是两件事。

填写配置只代表准备了凭据或来源地址。采集器、数据字段与权限需完成实际对接，才会变为可用。密钥仅保存在本机 .env，不填在前端或 Git 中。

视频如何进入选题池

  1. 按火车旅行、路线、卧铺、购票等主题发现候选视频。
  2. 保存平台视频 ID、原视频链接、作者、发布时间、取数时间及平台实际返回的指标。缺失指标保留空值。
  3. 按平台分别判断热度；有连续快照才能算增长速度。未校准阈值前只称为「视频候选」，不声称是爆款。
  4. 通过 AIHOT 外部导入接口收录，经筛选后由工作台只读公开结果。工作台的「采用标题」仅填入选题，不自动生成或发布。

AIHOT 的 industry/sources.json 已预留 rail-video-tiktok、rail-video-instagram、rail-video-youtube 三个 external 信源，均为停用状态。这是种子配置，当前运行数据库尚未导入它们；之后需由后台创建并试跑，再决定启用。既有营销案例保留，不冒充视频热点。

每日更新的边界

工作台读取 AIHOT 已收录内容，打开页面不会触发爬取或付费模型调用。目前没有新增定时采集任务；平台接通后再配置每日执行、失败提示和最近成功时间。电脑休眠或本地服务停止时无法保证更新。旧视频即使今天入库，也保留原发布时间。
