视频热点接入

接入代码已就绪。YouTube 使用官方搜索和统计接口；TikTok、Instagram 使用下方约定的数据服务格式。是否已连通，以工作台最近一次采集结果为准。

1. 配置本机凭据

编辑仓库根目录的 .env。该文件已被 Git 忽略，网页不会显示密钥；无需重启，保存后刷新工作台列表即可读取新配置。

YOUTUBE_API_KEY=
VIDEO_TRENDS_TIKTOK_FEED_URL=
VIDEO_TRENDS_TIKTOK_TOKEN=
VIDEO_TRENDS_INSTAGRAM_FEED_URL=
VIDEO_TRENDS_INSTAGRAM_TOKEN=
平台如何取得凭据当前接入范围
YouTube在 Google Cloud 创建或选用项目，启用 YouTube Data API v3，在「API 和服务 → 凭据」创建 API Key。API 限制选择 YouTube Data API v3；本服务由 Python 后端请求，不使用浏览器 HTTP referrer 限制。可按服务部署条件设置 IP 限制。关键词搜索一页（最多 25 条），再批量读取公开视频的累计播放、点赞和评论。地区表示可在该地区观看，不代表作者所在地。并非 Shorts 专属榜单。
TikTok选定有权使用的视频发现服务，将符合下面格式的 HTTPS 接口地址写入 FEED_URL；如需 Bearer 认证，将令牌写入 TOKEN。已实现标准 JSON 接收器；尚未选定、购买或实测具体供应商。普通账号视频查询不能当作全平台热点搜索。
Instagram同上，服务需返回 Reels 原链接和可提供的公开指标。已实现标准 JSON 接收器；尚未对接具体供应商，也不包含 Instagram 账号 OAuth 或 Insights。

2. TikTok / Instagram 数据服务格式

工作台发出 GET 请求，追加 q、region、days 和 limit=25。接口需按关键词、地区和时间筛选；不支持这些筛选的供应商需要适配，不能直接填入任意 API 地址。现有 URL 查询参数保留，同名筛选参数会被覆盖。

GET https://your-provider.example/videos?q=train+travel&region=GB&days=7&limit=25
Authorization: Bearer <本机 TOKEN，仅在配置时发送>

返回 JSON 对象与 items 数组。下面是格式示例，不会自动导入：

{
  "items": [
    {
      "title": "Train journey",
      "url": "https://www.tiktok.com/@example/video/1234567890",
      "author": "example",
      "published_at": "2026-11-10T09:00:00Z",
      "metrics_at": "2026-11-11T09:00:00Z",
      "metrics": {
        "views": 12345,
        "likes": 120,
        "comments": 8,
        "shares": null
      }
    }
  ]
}

必填：标题、平台原视频 HTTPS 链接。Instagram 链接格式为 https://www.instagram.com/reel/短码/。播放等指标必须为非负整数或 null，不能填「1.2K」。未知发布时间留空；时间必须包含时区。未提供指标时间时，界面标注为“指标取回时间”，不冒充平台更新时间。

接口最多返回 100 条、2 MB，单次请求超时 15 秒，不自动跟随重定向。任一记录格式错误时，本次该平台批次不入库，之前的数据保留；其他平台继续采集。无结果须返回 {"items":[]}，权限或额度问题应返回对应 HTTP 错误。

3. 在工作台试采集

  1. 打开「选题策划 → 视频热点」，刷新列表，确认目标平台显示“已配置 · 尚未采集”。
  2. 选择平台、关键词、地区和时间范围，点击「采集视频」。只请求已配置的平台。
  3. 核对最近成功时间、返回条数、原视频链接与指标。首次实测成功后再将该平台认定为可用。
  4. 选择「采用标题」带入脚本选题，人工调整后生成。引用视频不等于获得下载或复用授权。

配置缺失时按钮不可用；401 表示凭据问题，403 通常需要检查接口权限或额度，429 表示限流或额度问题。不要把密钥粘贴进聊天、前端或 Git。YouTube 额度以 官方搜索接口说明与项目控制台为准。

保存与刷新

结果保存在本机 output/video-trends.json，按平台视频 ID 去重，采用最新指标时间的记录。刷新页面可以继续查看；采集失败保留旧数据并显示错误和最近成功时间。列表同时保留 AIHOT 已收录的视频参考，AIHOT 断开不会影响平台采集结果。

仅手动采集，不设置定时任务；页面打开和“刷新列表”不请求平台。相邻采集至少间隔 30 秒。缓存最多 500 条，读取或采集时清理超过 30 天未重新取得的数据；服务停止期间不会执行清理。只显示平台原始累计指标，不推算增长率、不生成跨平台热度分，也不下载视频。
