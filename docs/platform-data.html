真实数据怎么接入

目前看板为演示数据，尚未接通平台授权与自动取数，也没有网页 CSV 上传入口。发布登记不等于已从平台核验或取得指标。

先跑通一条作品：后台导出 → 对账 → 复盘

  1. 运营从平台后台或 BI 导出数据，保留平台、账号、视频 ID、视频链接、播放数、取数时间与指标口径。
  2. 将「平台 + 账号 + 视频 ID」对应到工作台作品编号。当前程序使用「work_id + platform」对账，同一平台的作品编号必须唯一，不能按标题猜测。
  3. 技术人员备份整个 data/review/，在隔离的项目副本里整理真实发布记录与 CSV，避免混入演示记录。
  4. 运行复盘脚本，核对未匹配记录、作品数、取数时间、播放数和增量，再切换看板的数据来源。当前真实数据目录、来源标识及本机任务对应关系仍需开发。

现有脚本接受什么格式

发布记录沿用 data/review/published.json 的结构，每条包含 work_id、platform、account、script_id、title、genre、published、lines。另保留视频 ID 与链接的对应表；现有看板尚未自动读取这张映射表。

取数表使用 UTF-8 CSV，命名为 report_YYYY-MM-DD.csv：

work_id,platform,views,fetched_at,status

views 为截至取数时刻的累计播放数；时间统一约定时区，格式为 YYYY-MM-DD HH:MM。成功用 status=ok；失败用 status=error，views 留空。只有实际返回零播放才填 0。

.venv/bin/python review.py --no-ai

这条命令不调用模型，但会覆盖当前副本的 data/review/review.json。脚本会保留上次有效读数并标记取数失败，统计未匹配记录。现有界面硬编码了演示标签，不能只换 CSV 就声称生产接入完成；真实账号数据不要构建到公开 GitHub Pages。

自动取数：需要开发平台连接器

平台方式状态
TikTok授权用户的 video.list 与 /v2/video/query/，可请求播放、点赞、评论、分享等字段。官方说明连接器未开发
YouTube由频道持有人 OAuth 授权后调用 Analytics reports.query，按视频和日期取数；权限按官方要求配置，包括当前要求的 youtube.readonly 及相关 Analytics 读取权限。查询说明 / 授权说明连接器未开发
Instagram使用 Instagram Insights。账号与权限要求需按所选登录方式核实；本次官方文档请求被限流，未核实最新权限清单。官方入口连接器未开发

现有复盘只处理播放数及其变化；点赞、评论、分享还需扩展字段。各平台的播放口径分别保存；累计数与某时间段内的播放数不能混算。

需要你准备

目标平台与账号、账号授权人、开发者应用权限，以及一份真实数据样表。先拿一条真实作品与平台后台对账，成功后再扩大范围。账号密码无需提供，访问令牌仅留在服务端。
