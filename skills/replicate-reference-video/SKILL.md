# 参考视频逐镜头复刻

以用户提供的参考视频为唯一制作基准。保持制作结构，替换具体素材。例如参考是火车中景驶过，就选择另一段火车中景驶过；不要求同一车型、颜色，但不得用远景、静止、汽车或不符合方向的镜头替代。

## 开始执行

1. 获取可读取的参考视频和轨道项目路径；在当前目录与邻近目录定位 `rail-content-studio`，读取其 AGENTS.md。只有确实缺少参考视频或入口才向用户索取。
2. 为本次任务新建独立目录，保存 reference、关键帧、分析、素材映射、时间轴、草稿、导出与验收证据。不要覆盖项目现有 output/result.json、数据库、草稿或 data/skill.json。
3. 阅读 references/project-integration.md，复核当前源码，先读取旧素材库已审片段，再用 scripts/library_inventory.py 导出项目现有素材；保留来源和真实审批状态。不要把历史文档、静态展示页或抽样标签当成素材当前状态。
4. 读取 references/production-contract.md，创建本次 reference-spec.json 和 match-plan.json。记录输入文件摘要和工具版本以便复现。

## 拆解参考

- 用 ffprobe 获取画幅、帧率、时长、音轨；对可变帧率保留原始时间戳，以最终输出帧边界表示切点。
- 用场景变化检测提出切点候选，再逐镜头观看复核。淡入淡出、叠化、运镜不应直接误判成硬切。项目 distill_skill.py 只提供辅助统计，不能代替逐镜头分析。
- 逐镜头记录主体、动作、景别、场景、构图、运动方向、机位与运镜、光线、色调、开始帧和结束帧。所有帧区间采用左闭右开。
- 逐个文字事件记录原文、断句、时间、字体文件与字体名称、字重、字号、归一化位置、文本框、对齐、颜色、描边、阴影、行距及动画。区分字幕、花字、标识和其他叠加层，允许跨镜头事件。
- 结合音频听辨和转写记录配音原文、停顿、语速、情绪、音色描述及事件时间；单独记录音乐、音效和音量变化。自动转写必须核对。
- 对字体身份记录 verified / inferred / unknown；只有字体文件、工程元数据或可核对依据才能 verified。不得把视觉相似字体当成已确认字体。无法确认先列差异，继续不依赖它的工作。
- 不自动克隆特定真人声音。默认使用可用合成音色；与参考音色不一致必须披露。模型调用走项目 llm.model_config()，不要回显凭据。

## 在已有素材库匹配

- 按 `references/material-search-policy.json` 的 `inventory_order` 先查旧素材库已审片段，再查项目正式库及历史素材。库存候选已能满足完整条件时，不另起外部搜索任务。已有库不足时，先调用旧素材库 Agent 补充，再考虑已配置的项目来源；新素材沿用真实审批流程，不冒充审批人或自动批准。
- 先按主体、动作和场景召回，再实际观看候选片段，检查景别、方向、运镜、构图、时长及地点。标签与八帧抽样都不能证明连续动作或精确片段边界。
- 给每个镜头保存至少一个可用候选或具体缺口；记录素材 ID、路径、来源、src_in/src_out、证据时间、硬条件检查结果。
- 所有硬条件必须通过。分数仅用于通过硬条件后的排序。允许主体型号、颜色、外观不同；不允许用总相似分掩盖景别或动作不符。
- 默认正常速度、无循环、无定格、无镜像；需要变更先说明对参考的影响。裁剪后必须重新判断景别，避免把主体截断。素材不足不得靠冻结尾帧或循环冒充通过。
- 保留输出画幅为硬条件，允许高分辨率横屏源经裁切满足竖屏输出。旧库 `orientation` 只筛源文件画幅，因此搜索请求留空；按最终裁切后的主体、景别、动作和构图判定，不因源文件横竖屏直接拒绝。
- 输出 matched / transform_required / gap。缺口需说明缺少的具体镜头要求；不要编造 ID、起止时间或审批记录。

## 联网补充缺口素材

1. 在运行时读取并校验 `references/material-search-policy.json`，调用 `scripts/plan_material_search.py` 的 `build_plan(analysis, technical, policy)`。保留每个镜头的完整主体、动作、景别、场景、方向、运镜、构图、准确帧数/有理数时长、目标分辨率和地点，以及原始需求、Skill摘要和摘要哈希。未明确为静态需求时默认搜视频；只有明确 `motion_required=false` 或 `static_requirement=true` 才可搜图，运动需求与图片声明冲突时停下该镜头搜索。
2. 使用短英文词召回，用完整 `request.query`/`requirements` 后验。不要把长描述原样塞入搜索引擎，也不要因缩短检索词而删掉硬条件。英文词可来自分析给出的 `queries` 或基础英文标签；缺失时先补真实翻译。请求承载不下完整条件时标记 blocked，不静默截断。
3. 先复用旧素材库 Agent；其真实来源由当前服务配置与任务记录确认，可包含 Commons 和 Internet Archive。已配置的项目来源可补充。动态镜头使用 video，静态图片使用 image/fixed；不能把图片裁切、平移或定格当成原参考的连续动作。提交前复核服务连通性和实际支持的内部轮数。
4. 为每个请求计算 SHA-256 `request_fingerprint`，在提交前持久化请求、完整条件、策略版本、任务预留记录；收到任务 ID 后立即绑定。恢复执行先读已有记录和旧库实际任务，已运行的请求只轮询、恢复或报告结果，不重复提交。提交结果不明时先核对旧任务 payload，不能用新建任务猜测重试。
5. 每镜头同一套完整制作要求（semantic_plan_id）所有来源合计最多 **2 个外部任务**；旧实验请求若缺少完整硬条件或提交证据，保留候选、任务身份和来源冷却，但不能算作这套完整要求已执行。策略文字或版本号变化不能重置预算。每个旧 Agent 任务内部最多 **3 轮**。第二个外部任务只用于第一个任务已成功完成但无合格素材，且根据拒绝原因调整了查询的情形。每任务最多3组备选词、20候选、5条自动分析；严格采用策略中的有限并发和轮询间隔。不要把内部3轮乘成无限重试，也不要重复刚失败的原词新建任务。
6. 将 HTTP 429 与临时网络故障独立于素材无结果处理。按策略指数退避；实际等待至少为本次指数等待、`Retry-After`、`cooldown_until` 的最大值，不能用客户端上限缩短服务端等待。同一来源在全部历史任务间共享冷却；Archive 补源等待不阻塞仍健康的 Commons 主搜索，来源未知时保守等待。调用 `POST /api/commons/resume-search` 恢复原任务，并保存真实 `result.network_retries` 和 `cooldown_until`；最多3次网络恢复，不消耗第二个外部任务。达到等待/恢复预算时保留任务身份和具体错误，报告延后或失败，不紧密重试。
7. 只有搜索正常完成、候选为零且无来源错误才记 `no_results`；有候选但硬条件全不符记 `no_match`；TLS/DNS、限流、配置、下载或分析出错记 `failed`/`rate_limited`。不能把失败包装成“网上没有素材”。检查连续源片段、真实 MIME、最终裁切、时长、地点及授权，八帧抽样和标签仅用于初筛。
8. 将内容合格但未获真实审批的候选记 `pending_approval`，提交候选区间和匹配证据供用户审核；继续不依赖该素材的工作。用户审批后重新读取正式状态、文件和许可，更新素材 ID、区间与 match-plan。拒绝或停用的素材不得选入新工程，不伪造审批记录。

规划器只生成可审计请求，不提交任务、不搜索、不审批。调用方式与字段约定见 `references/project-integration.md`；执行器必须落实去重、预算和同任务恢复，不能把“生成计划”当成“找到素材”。

## 编排与输出

1. 按参考建立逐帧时间轴；先固定镜头边界，再安排声音和文字，不以重新生成配音的长度反向改变镜头时长。
2. 依据实际接口能力选择项目原有粗剪或独立、隔离的渲染流程。仅在完全满足规格时使用现有导出器；不支持的字体、位置、转场、音乐必须在本次隔离流程补齐，或明确列为阻塞。
3. 能用原参考音轨且符合用户用途时可以保留；否则使用现有配音能力并验证时长。不得将音乐、音效和对白混为一项“已有音频”。无法分离时如实记录。
4. 采用明确字体文件与渲染字体目录，检查字体实际加载和缺字；不能只填写字体名称。按画幅换算归一化位置。静态字幕可以采用 ASS；复杂动效使用实际支持的工具并检查成片。
5. 在渲染之前运行 scripts/check_plan.py 校验时间和素材证据。检查脚本通过只代表结构检查通过。
6. 输出隔离草稿和 MP4（工具支持时），分镜表、reference-spec.json、match-plan.json、素材来源与使用区间、可复用字体/声音/字幕参数、验收报告及差异清单。未产出成片不得声称成片完成。

## 对照验收

- 重新探测导出文件，逐镜头比较数量、顺序、语义、景别、动作、方向、运镜和构图；不能仅比较文件时长。
- 默认镜头切点误差不超过一个输出帧；这是本 Skill 的工程验收默认值，不是参考视频实测。字幕与音频事件使用同样的时间对齐基线；用户要求更严格时收紧。
- 并排查看参考和输出的镜头起点、中点、终点以及所有字幕样式/转场变化处，并完整播放核对声音、字幕和节奏。关键帧相似不等于动作合格。
- 分别报告结构、画面、字幕、字体、配音、音乐音效、转场、成片播放的 pass / gap / unverified。存在硬条件缺口、未知字体或未验证声音时，不得报告完全一致。
- 将真实视频验证、离线夹具测试和未完成检查分开。没有真实参考视频时只完成 Skill 与离线自检，不虚构视频拆解结果。
